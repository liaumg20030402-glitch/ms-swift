> 配套实验：`my-project/homework`（Qwen3.5-4B 在 hendrycks_math 上做 LoRA 微调）

## 1. LoRA 原理

LoRA (Low-Rank Adaptation) 的核心思想是：在大模型微调时，不直接修改原模型参数，而是通过“旁路”的低秩矩阵来模拟参数的变化。**研究表明，大模型在特定任务上微调时，参数的变化量其实是一个低秩（Low-Rank）矩阵。这意味着，我们不需要调整全部参数，只需要调整极少量的关键维度即可。**

假设大模型原有的一个权重矩阵为 W₀（维度为 d × k）。在微调时，参数的变化量为 Δ W。微调后的实际权重为：$W=W_{0}+\Delta W$
LoRA 的做法是，将高维的 Δ W 拆解为两个低维矩阵 A 和 B 的乘积：$\Delta W=B\times A$

**核心假设**：大模型适配下游任务时，权重的更新量 ΔW 是**低秩**的——即 ΔW 可以用两个小矩阵的乘积近似。

对一个原始权重矩阵 `W ∈ R^{d×k}`（冻结不训），LoRA 在旁边加一条低秩支路：

```
W' = W + ΔW = W + (alpha / r) · B · A
     A ∈ R^{r×k}   (降维, 高斯分布随机初始化)
     B ∈ R^{d×r}   (升维, 零初始化 → 训练开始时 ΔW=0)
     r << min(d, k)
```

训练时**只更新 A、B**，原权重 W 保持冻结。

- **参数量**：从 `d×k` 降到 `r×(d+k)`，通常只占全参数的 0.1%~1%（本实验 16.2M / 4555M ≈ 0.36%）。
- **省显存**：不需要为 W 存优化器状态（Adam 的一阶/二阶动量）。
- **可插拔**：训练产物是小小的 adapter，推理时叠加到底模上；不改原权重，可随时卸载/切换。
- **B 初始化为 0**：保证微调起点等于原模型，训练平滑。是为了保证 在训练开始的第一步，LoRA 旁路对原模型没有任何副作用。因为 B = 0，所以 Δ W = B × A = 0。此时前向传播：Output = W₀ x + 0 = W₀ x。结果：训练刚开始时，模型的行为与原微调前的基础模型（Base Model）完全一致。如果 B 不用 0 初始化，模型在第一步就会受到随机噪声的干扰，破坏原有的预训练能力。

LoRA 的降维本质上是：先压缩（A 矩阵，高维 $\rightarrow $ 低维），再解压（B 矩阵，低维 $\rightarrow $ 高维）。
- 矩阵 A（降维层）：**它的任务是从原本极其宽阔的高维空间（如 4096 维）中，“抽取”或“投影”出 8 维的特征。使用高斯随机初始化，相当于给模型在低维空间中初始化了 8 个不同的观察视角（基底）。**

- 矩阵 B（升维层）：**它的任务是把这 8 个视角的信息，重新放大映射回原空间的 4096 维。让它初始化为 0，意味着在初始状态下，模型“选择不把这些新视角的信息混合进原模型”。**

  > 是的，你的理解完全正确！**FFN 层的 Up/Gate/Down 是先升维再降维**，而 **LoRA 则是先降维再升维**。这两者虽然都涉及维度的改变，但由于**核心目的和所处的阶段**完全不同，导致了相反的设计。
  >
  > 以下是它们的核心区别和背后的逻辑：
  >
  > ## 1. 现代大模型 FFN 层：先升维再降维
  >
  > 以 LLaMA/DeepSeek 为代表的现代大模型中，FFN 层通常采用 **SwiGLU 结构**。它的处理流程是：
  >
  > ```unset
  >                     ┌───► Up Projection ───┐
  > 输入 (d) ──┬────────┤                      ├─► 逐元素相乘 (⊗) ──► Down Projection (d)
  >            └────────► Gate ──► Activation ─┘
  >          [升维到 4d~8d]                                           [降维回 d]
  > ```
  >
  > - 具体操作
  >
  >   ：
  >
  >   1. **Up Gate (升维)**：输入维度为 d。首先通过 `Up` 矩阵和 `Gate` 矩阵，将维度放大到隐藏层维度（通常是 4d 到 8d，比如从 4096 升到 11008）。
  >   2. **激活与融合**：对 `Gate` 分支进行激活函数处理（如 Swish），然后与 `Up` 分支进行逐元素相乘（Element-wise Product）。
  >   3. **Down (降维)**：通过 `Down` 矩阵，将高维特征压缩回原始维度 d。
  >
  > - 为什么要先升维？
  >
  >   - **提高非线性表达能力**：神经网络在低维空间进行复杂的非线性映射（激活函数）时，容易丢失信息。将特征投影到极高维的空间，能让模型更容易找到复杂的模式和分类边界，**就像把揉成一团的纸巾展开一样**。
  >
  > ------
  >
  > ## 2. LoRA（低秩自适应）：先降维再升维
  >
  > LoRA 是一种微调技术，它是对大模型中原有高维矩阵（比如 Attention 的 $W_q, W_v$ 或 FFN 的 `Up/Down`）的**低秩近似旁路**。它的处理流程是：
  >
  > ```unset
  >            ┌───► 冻结的原始高维矩阵 W_0 (d × d) ───┐
  > 输入 (d) ──┼                                       ├─► 相加 (Y = W_0·X + △W·X)
  >            └───► 矩阵 A (降到 r) ──► 矩阵 B (升到 d) ┘
  >                        [LoRA 旁路 △W = B × A]
  > ```
  >
  > - 具体操作
  >
  >   ：
  >
  >   - 矩阵 A：将输入维度 d 降维到非常低的秩 r（如 r=8 或 16）。
  >   - 矩阵 B：将维度从 r 重新升维回原始维度 d。
  >
  > - 为什么要先降维？
  >
  >   - **极大地减少计算量和参数量**：如果直接训练一个和原本一样大的 d × d 矩阵，显存会爆炸。LoRA 认为模型更新的有效信息存在于一个“低维子空间”（Low Intrinsic Rank）。
  >   - **通过低秩分解实现高效存储**：直接更新一个 4096 × 4096 的矩阵需要 1600 万个参数。而通过 A (4096 × 8) 和 B (8 × 4096) 分解后，参数量变成了 2 × 4096 × 8 = 65,536，**直接缩减了 250 倍**。
  >
  > ------
  >
  > ## 💡 核心总结与对比
  >
  > | 特性         | 大模型 FFN 层                                    | LoRA 旁路微调                              |
  > | :----------- | :----------------------------------------------- | :----------------------------------------- |
  > | **维度路线** | **先升维，后降维** （d → 4d → d）                | **先降维，后升维** （d → r → d）           |
  > | **根本目的** | **扩充空间，拟合复杂特征**（知识容量）           | **降低资源消耗，寻找本质变化**（低秩近似） |
  > | **参数状态** | 属于大模型的主干，参数量极大且被**冻结或预训练** | 属于微调附加层，参数量极小且**可训练**     |
  >
  > 如果感兴趣，我们接下来可以聊聊：
  >
  > - 为什么 LoRA 能够**无损合并（Merge）**回大模型主干，实现零推理延迟
  > - FFN 层中的 SwiGLU 激活函数，是如何与 Up/Gate/Down 配合工作的

在深度学习的工程实践中，LoRA 旁路本质上可以看作是一个微型的 全连接层（Linear Layer）：矩阵 A 是输入层 $\rightarrow $隐藏层。矩阵 B 是隐藏层 $\rightarrow $输出层。在主流深度学习框架（如 PyTorch）中，线性层的默认初始化习惯就是：权重（Weight）采用某种随机分布（如 Kaiming 或 Xavier），而偏置（Bias）初始化为 0。让最末尾的输出端（B 矩阵）为 0 来拦截随机噪声，完美契合了这一经典的工程设计直觉。

> lora初始化为什么不能把A矩阵初始化为0，B随机，或者AB都初始化为0?
>
> 在大模型微调（LoRA）中，标准的初始化策略是：**A 矩阵采用高斯随机分布初始化，B 矩阵全初始化为 0**。
>
> 你提到的两种替代方案——“**A为0、B随机**”或“**AB都为0**”——虽然在数学形式上也能让 LoRA 初始状态的输出为 0，但它们在**反向传播（训练）时会遭遇致命问题**，导致模型无法正常学习。
>
> 以下是具体的底层逻辑和原因：
>
> ------
>
> ## 1. 为什么“A、B都初始化为0”不行？（破坏对称性）
>
> 如果 A 和 B 全都初始化为 0，就会触发神经网络中最经典的**“对称性无法打破”（Symmetry Breaking）**问题。
>
> - **前向传播**：$\Delta W = B \times A = 0 \times 0 = 0$。此时 LoRA 相当于没开启，基座模型正常输出。
>
> - 反向传播（梯度更新）
>
>   ：根据矩阵求导的链式法则：
>
>   - A 矩阵的梯度取决于 B 矩阵：$\frac{\partial L}{\partial A} = B^T \times \text{后级梯度}$
>   - B 矩阵的梯度取决于 A 矩阵：$\frac{\partial L}{\partial B} = \text{后级梯度} \times A^T$
>
> - **致命后果**：因为初始状态下 $A=0$ 且 $B=0$，带入上述公式会发现，**A 和 B 的梯度在第一步计算时全都是 0**！梯度为 0 意味着权重永远不会被更新，整个 LoRA 模块直接“卡死”，完全无法学习任何新知识。
>
> ------
>
> ## 2. 为什么“A为0，B随机”也不行？（秩塌陷与表征受限）
>
> 这个方案看起来避开了全 0 的陷阱，但它会带来更隐蔽的**“物理机制不对称”**与**“梯度回传阻断”**问题。
>
> 我们可以从两个角度来分析：
>
> ## 角度 A：阻断了对基座模型前级权重的梯度回传
>
> 在 Transformer 中，LoRA 的输入 $X$ 是从前一层传过来的。
>
> - 当 A 矩阵为 0 时，前向传播中 $X$ 乘以 A 瞬间变成了 0（$AX = 0$）。
> - 到了反向传播时，损失函数对输入 $X$ 的梯度需要经过 A 矩阵回传：$\frac{\partial L}{\partial X} = \frac{\partial L}{\partial (AX)} \times A^T$。
> - **致命后果**：因为 $A=0$，**LoRA 这条支路回传给前一层输入 $X$ 的梯度瞬间变成了 0**。这会导致基座模型前层网络的参数无法感知到 LoRA 层的梯度调整，破坏了联合训练的动态平衡。
>
> ## 角度 B：B 矩阵的“随机性”在第一步被瞬间抹杀
>
> - 同样根据梯度公式，B 矩阵的梯度为：$\frac{\partial L}{\partial B} = \text{梯度} \times A^T$。
> - 因为 $A=0$，所以**在第一步更新时，B 矩阵的梯度完全为 0**，B 的权重保持不变（依然是最初的随机值）。
> - **此时只有 A 矩阵能拿到有效的梯度（因为 $B$ 是随机的，不为0）**：$\frac{\partial L}{\partial A} = B^T \times \text{梯度}$。
> - **致命后果**：这意味着在训练刚开始时，只有 A 在单相思地更新，而 B 像块死石头一样无法根据误差进行调整。这种不对称性极大增加了优化的难度，容易导致收敛缓慢或陷入糟糕的局部最优解。
>
> 
>
> ------
>
> ## 3. 为什么“A随机，B为0”是最完美的方案？
>
> LoRA 的精妙之处就在于，标准方案完美解决了上述所有痛点：
>
> 1. **初始输出为 0**：$\Delta W = B \times A = 0 \times \text{随机} = 0$，保证了微调刚开始时，大模型的性能完全不受到扰动。
> 2. **梯度全线畅通：**
>    - 因为 A 随机，所以 B 的梯度 $\frac{\partial L}{\partial B} \propto A^T \neq 0$，B 可以在第一步就立刻开始跟着学习。
>    - 因为 B 初始为 0，所以 A 的梯度在第一步虽然是 0（$\frac{\partial L}{\partial A} \propto B^T = 0$），但**只要 B 在第一步变成了非 0 值，在第二步迭代时，A 就会立刻激活并获得梯度**。
> 3. **打破对称性**：A 的随机性为模型注入了探索不同低秩子空间（Low-rank Subspace）的可能性。
> 4. 标准LoRA更喜欢 A 随机、B=0，主要因为：只让 A=0、B 随机在数学上可以训练，第一步先更新 A；第二步开始 B 也获得梯度。但标准LoRA通常选择“输入侧随机、输出侧置零”，优化动态更自然。
>    - A 是降维投影，随机初始化后，第一步就能得到非零的低维特征 Ax；
>    - B 是升维输出投影，置零可以保证LoRA残差分支初始输出严格为0；
>    - 第一步直接学习如何把随机低维特征映射到输出空间；
>    - 这种设计与很多残差Adapter“内部特征非零、输出层置零”的初始化习惯一致；
>    - 是原始LoRA采用并经过实践验证的稳定方案。

# LoRA与QLoRA区别

| LoRA                  | QLoRA                   |
| --------------------- | ----------------------- |
| 基座通常FP16/BF16     | 基座通常4bit            |
| 冻结基座，训练LoRA    | 同样只训练LoRA          |
| 权重显存相对较高      | 基座权重显存大幅降低    |
| 计算更直接            | 计算时需要反量化        |
| LoRA参数通常BF16/FP16 | LoRA参数仍通常BF16/FP16 |

QLoRA并不是“把LoRA参数量化成4bit”，而是：

> 将冻结的基座模型量化，LoRA参数仍以较高精度训练。

## 2. 训练关键参数（swift sft）

| 参数 | 含义 | 调参建议 |
|---|---|---|
| `--tuner_type lora` | 用 LoRA（相对全参数微调） | 固定 |
| `--lora_rank` (r) | 低秩支路的秩，**控制容量** | 8/16/32/64。小=省参省显存、容量低；大=容量高、更易过拟合。常用 8 起步 |
| `--lora_alpha` | 缩放系数，有效缩放 = `alpha/r` | 常设 `alpha=2r`（本实验 32/8=4 倍）或 `alpha=r`（=1 倍）。alpha 越大，LoRA 的影响越强 |
| `--lora_dropout` | LoRA 支路的 dropout，防过拟合 | 0.0~0.1，老师用 0.1 |
| `--target_modules` | 把 LoRA 注入哪些线性层 | `all-linear`=所有线性层（q/k/v/o/gate/up/down 等）；也可只注意力层 `q_proj k_proj v_proj o_proj`，容量更小、更不易破坏基座 |
| `--learning_rate` | 学习率 | LoRA 典型 `1e-4 ~ 2e-4`。**对已经很强的基座，过高的 lr 会破坏原能力**（见第 5 节） |
| `--num_train_epochs` | 训练轮数 | 1~3。窄数据上 epoch 越多越容易过拟合 |
| `--per_device_train_batch_size` | 每卡每步样本数 | 受显存限制，OOM 就调小 |
| `--gradient_accumulation_steps` | 梯度累积步数 | **有效 batch = per_device × grad_accum × 卡数**。本实验 2×8×4=64 |
| `--max_length` | 序列截断长度 | 覆盖大部分样本即可，越长越占显存 |
| `--warmup_ratio` | 学习率预热比例 | 0.03~0.1 |
| `--lr_scheduler_type` | 学习率调度 | `cosine`（缓降）常用 |
| `--group_by_length` | 按长度分组以减少 padding | Qwen3.5 transformers 后端不支持 packing 时用它提速（loss 曲线会轻微抖动） |
| `--use_liger_kernel` | 融合算子 | 大词表模型省显存的关键（避免物化 25 万词表的 logits） |

**有效 batch 的理解**：`per_device_train_batch_size` 不是全局 batch，一次真正的梯度更新用的是 `per_device × grad_accum × GPU数` 条样本。要省显存又保持训练动态，就「调小 per_device、调大 grad_accum」。

## 3. 推理/评测采样参数

| 参数 | 含义 | 评测准确率时的建议 |
|---|---|---|
| `temperature` | 采样温度，控制随机性 | **0 = greedy（贪心，确定性）**：每次结果一样，准确率可复现，**推荐用于评测**。`0.7`（老师设置）= 带随机性，同一题多次跑结果会变，准确率会有 ±波动 |
| `top_p` | nucleus 采样，只从累积概率 top-p 的词里采 | **仅在 temperature>0 时生效**。老师用 0.9 |
| `do_sample` | 是否采样 | temperature>0 时为 True；greedy 时为 False |
| `max_new_tokens` | 最大生成长度 | 非思考模式 512~1024 足够；思考模式要 ≥4096（推理链长） |

**为什么评测建议 greedy 而非老师的 0.7**：做「准确率对比」时，随机采样会让 baseline 和各 checkpoint 的数字都带噪声，不利于公平比较。greedy 去掉随机性，差异才反映真实能力。老师 notebook 用 0.7+0.9 是通用默认值，若要严格对齐老师，evaluate.py 加 `--temperature 0.7 --top-p 0.9` 即可（但建议主结果用 greedy，附录可补一组 0.7 的）。

## 5. ⚠️ 为什么 LoRA 后准确率反而下降了

本实验现象：baseline 58.78% → epoch1 46.96%，且 epoch 越多越差。这是一个**真实且常见**的现象，值得写进报告分析：

**原因**：Qwen3.5-4B 是已经很强的指令/推理模型，本身数学能力就高（58.78%）。在**窄数据集**（只有 MATH 解答）上用**偏高的 lr（1e-4）× 多个 epoch**做 SFT，会让模型**过拟合数据集的解答风格、丢失原有的通用推理能力**——即「灾难性遗忘」。epoch 越多越差，正是过拟合的确凿信号。

**这不是数据量不够的问题**，7500 条对 LoRA 足够；加更多数据（甚至污染 test）都救不了，反而掩盖问题。

**诊断方法（先做这一步）**：打开 `infer_output/pred_*.jsonl`，逐条看微调后模型的 `generation`，判断错因属于哪类：
1. **格式坏了**：不再输出 `\boxed{}`、或啰嗦跑题 → 训练把输出格式带偏了，extract 抓不到答案；
2. **boxed 但答错**：格式对、答案错 → 真实推理能力下降。

**缓解手段**（按优先级，一次改一项再对比）：
1. **降学习率**：`1e-4 → 2e-5 或 1e-5`，强基座最关键的一招；
2. **减 epoch**：先只训 1 个 epoch（甚至更少 step），别 3 个；
3. **降容量**：`lora_rank 8`、`target_modules` 只挂注意力层（`q_proj k_proj v_proj o_proj`），少动 MLP，减少对基座的破坏；
4. 评测确保非思考模式与训练一致（已是）。

目标不是「一定要超过 58.78%」，而是理解并展示「强基座上 LoRA 的得失」，这本身就是高质量的实验分析。

---

## 6. 数据划分：不要把 test 混入 train

针对「从 test 抽一部分当测试，还是把 test 混入 train」的纠结：

**标准且唯一推荐的做法**：数据集本身已经有干净的 `train`(7500) / `test`(5000) 划分——
- **训练**：用全部官方 train（不必单独切验证集，老师也没切；要监控 loss 可从 train 里切一小撮当 val）；
- **评测**：用官方 test。

**不要把 test 的一部分混进 train**：这是**数据泄漏**，会让 test 指标虚高、且与「从没见过任何数据的 baseline」不再可比，报告结论不可信。

**「训练数据更多结果会不会更好」**：在这个任务里不会——瓶颈是超参和强基座，不是数据量（见第 5 节）。想让评测更快，就固定抽 test 的一个**随机子集**（如 1000 条，baseline 和所有 checkpoint 用同一子集）来比较，这完全合规，也是老师做法（他只评 64 条）。
